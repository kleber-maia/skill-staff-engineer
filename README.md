# staff-engineer

Skills, scripts, and guardrails that make AI coding agents work like a **staff engineer** for the
person they help, whether that person is an engineer or has never opened a terminal.

- **Harness-neutral.** Ships as a Claude Code plugin (skills, slash commands, subagents, hooks)
  *and* as plain [Agent Skills](https://agentskills.io) plus an `AGENTS.md` block that Codex,
  Cursor, Gemini CLI, and other agents pick up.
- **Stack-agnostic.** A small config maps the toolkit's checks to *your* commands. Detection
  covers Node, Python, Go, Rust, Ruby, Java/Kotlin, Swift, PHP, Makefiles, and static sites.
  Anything unknown becomes a plain-language question for the operator.
- **Enforced, not just described.** Zero-dependency Node scripts refuse out-of-order steps:
  no tests before the operator saw a preview, no save without a passing gate and an explicit
  "ship it".

## Install

Point your agent at this repository and say **"install staff-engineer into this project"**. The
agent follows [AGENTS.md](AGENTS.md). Or do it yourself:

```bash
# any agent, any stack
git clone https://github.com/<owner>/skill-staff-engineer ~/staff-engineer
cd your-project
node ~/staff-engineer/scripts/cli.mjs install --target . --dry-run   # review
node ~/staff-engineer/scripts/cli.mjs install --target . --yes
node .staff-engineer/cli.mjs doctor                                   # answer the questions
```

```bash
# Claude Code plugin (adds slash commands, subagents, and hooks)
claude plugin marketplace add <owner>/skill-staff-engineer
claude plugin install staff-engineer@staff-engineer
# then, inside a project:  /staff-engineer:install
```

```bash
# npx
npx github:<owner>/skill-staff-engineer install --target .
```

Requirements: Node.js 20+ and git in the target project. No npm packages are installed.

## What gets installed

```
your-project/
├── .staff-engineer/        vendored CLI, rules, templates, config.json, exceptions.json
├── .agents/skills/         staff-engineer, grill-me, solid, simplify, handoff, data-safety, spec-and-plan, install
├── AGENTS.md               a managed block (your text outside the markers is untouched)
├── CLAUDE.md               "@AGENTS.md" (created only if missing)
└── .gitignore              a managed block for toolkit backups
```

Session state, verification logs, and receipts live under `.git/staff-engineer/`, so they are never
committed and work in worktrees.

## The lifecycle

```
begin ──▶ grill-me ──▶ brief ──▶ build first pass ──▶ preview ──▶ operator feedback
                                                        ▲               │
                                                        └── revise ◀────┤ change requests
                                                                        ▼ "looks good"
                                             finalize (STAFF_ENGINEER_PREVIEW_APPROVED=1)
                                                                        │
                    tests ──▶ simplify (4 lenses) ──▶ docs ──▶ lifecycle gate ──▶ verify --mode full
                                                                        │
                                                    handoff ──▶ operator says "ship it"
                                                                        ▼
                                             ship (STAFF_ENGINEER_CHANGE_APPROVED=1) ──▶ one commit
```

| Command (`node .staff-engineer/cli.mjs ...`) | Refuses when |
|---|---|
| `begin "<concern>"` | another concern is open or saved-but-unsynced; pre-existing dirty files are fingerprinted and protected |
| `brief --outcome --accept ...` | no outcome or no acceptance check |
| `preview` | no brief; web preview not reachable |
| `verify --mode fast\|full` | tests before feedback when source changed; unconfigured gates; another run in progress |
| `finalize` | preview not presented; missing `STAFF_ENGINEER_PREVIEW_APPROVED=1` |
| `lifecycle` | debug output, suppressions, loose types, unfinished markers, broad helper files, oversized files, missing docs or tests, protected/never-stage paths, partial staging, stale exceptions |
| `ship "<message>"` | missing `STAFF_ENGINEER_CHANGE_APPROVED=1`; lifecycle findings; receipt does not match the staged code; too many areas without a broad-change reason |

Every command accepts `--json` and returns `{ ok, code, data, operator, agent, errors }`: one plain
sentence for the operator, one next-step hint for the agent. Exit codes: 0 ok, 1 refused, 2 tooling
problem, 3 a check failed.

## Configuration

`.staff-engineer/config.json` is generated by detection and completed through `doctor`:

```json
{
  "operator": { "mode": "non-technical" },
  "gates": {
    "lint": { "cmd": "npm run lint" },
    "test": { "cmd": "npm test", "affected": "npx vitest run {files}" },
    "e2e": null
  },
  "preview": { "kind": "web", "cmd": "npm run dev", "url": "http://localhost:3000" },
  "paths": { "source": ["src/**"], "tests": ["**/*.test.*"], "protected": [".env", ".env.*"] },
  "rules": { "maxAddedLinesPerFile": 300, "requireTestPerSourceChange": true, "maxConcernCategories": 2 }
}
```

A gate that is an object runs. `null` means "not applicable, confirmed". A missing gate is a
question `doctor` asks. `preview.kind` is `web`, `command`, or `manual`, so libraries and CLIs are
first-class. Language rules live in `rules/languages.json`; disable any with `rules.disable` or
record a permanent exception with a reason via `exception add`.

## Claude Code extras

The plugin adds `/staff-engineer:begin`, `brief`, `preview`, `revise`, `finalize`, `simplify`,
`verify`, `handoff`, `ship`, `status`, `doctor`, `install`, `abort`; subagents for the four simplify
lenses, a read-only explorer, and a verifier; and hooks that inject session state at start, deny
dangerous commands (force pushes, hard resets, recursive deletes, piping downloads into a shell),
protect secrets, block tests before feedback, and block raw commits while a concern is open. Hooks
fail open and do nothing in projects without an install.

## Repository layout

```
skills/        canonical Agent Skills (also copied into projects)
commands/      Claude Code slash commands
agents/        Claude Code subagents
hooks/         plugin hook registration
scripts/       zero-dependency CLI (cli.mjs, commands/, lib/, hooks/) and its tests
rules/         language and structural rule tables
templates/     managed AGENTS.md block, definition of done, handoff, spec, plan
schemas/       JSON schema for config.json
fixtures/      sample projects and diffs used by the tests
docs/          lifecycle, design rationale, FAQ
```

Development: `npm test` runs the unit tests and `scripts/lint-toolkit.mjs`.
